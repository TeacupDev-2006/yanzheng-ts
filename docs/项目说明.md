## 1. 基本信息

### 1.1 项目名称

研证 · 毕业论文评卷团 Agent（YanZheng Review Board）——TS 重构版，原生运行于 AGH 底座。

### 1.2 项目摘要（一句话 + 一段）

**一句话**：用 Agnes + AGH 把"高考阅卷式"多 Agent 交叉评审制度移植到毕业论文质量审查——门检打回、4 团 13 员互盲评卷、两级仲裁、作假证据链一票否决，全程留痕可复核。

**一段**：毕业论文评审长期依赖少数导师个人判断，缺乏像高考阅卷那样的制度性质量保障。研证将高考阅卷的三项核心制度（多人独立评分、分差仲裁、舞弊一票否决）移植为多 Agent 流水线：① 硬性门检（字数 / 分块查重 / 必备章节，纯确定性程序）；② 4 个评审团 13 名 LLM 评卷员互盲并行打分（内容 40 / 结构 30 / 语言 15 / 规范 15）；③ 团内仲裁（分差 >15% 触发团长复核、剔除离群分）；④ 总仲裁（合成总分 + 作假证据链复核一票否决 + 修改优先级路线图）；⑤ 输出单文件 HTML 交互报告与 PPT。系统以 TypeScript 全量重构并原生注册为 **AGH（Agnes Harness）插件**，评卷主流程在 AGH daemon 内经 AI 助手自主编排执行，全程留执行记录。

### 1.3 问题来源与目标

- **问题来源**：毕业论文评审公信力不足——单人评审主观波动大、AI 代写作假难发现、评审过程不可追溯。团队在课程实践中多次见到"摘要与正文数据不一致""捏造参考文献"未被发现的实际案例。
- **任务目标**：
  1. 端到端可运行的论文评审系统：输入论文文件，输出结构化评分 + 否决裁定 + 修改路线图；
  2. 评审过程**制度化可复核**：每一步有确定性规则或留痕证据，不是黑盒打分；
  3. 作假检测优先：数据矛盾、捏造引用、题文不一致等硬伤触发一票否决而非仅扣分；
  4. 原生适配 AGH 底座，形成可复用的"多 Agent 制度化评审"插件范式。

## 2. 技术信息

### 2.1 AGH 的作用（非外围辅助，评卷主流程所在）

- **插件承载**：研证以 `@yanzheng/agh-plugin@0.6.1` 按官方插件规范注册 4 个工具（`thesis_gate` 门检 / `thesis_sections` 章节切分 / `thesis_dedup` 分块查重 / `thesis_review` 全流程评卷），经 `package install → trust → enable` 装入 daemon，状态 `actual=running trusted=true`。
- **自主编排**：AGH 会话中 AI 助手自主规划并连续调用研证工具链完成评卷主流程（≥3 连续步骤），非人工逐步驱动。
- **权限审批**：`thesis_review` 涉及文件写出，执行前经 AGH 权限审批流（`requiresApproval`，实测每次触发审批记录）。
- **执行留痕**：全程产生 AGH 执行记录（会话级 JSONL，含每次工具调用参数、结果与审批决定），可导出归档——即"运行证据"。
- **沙箱与信任**：插件经完整性哈希（integrity + capabilityHash）信任锚定，来源变更即失效。

## 5. 测试样例（正常 / 边界 / 失败）

### 5.1 正常样例

```bat
node packages\cli\bin\yanzheng.mjs testdata\demo_paper.txt --out 正常报告.html
```
实测：金标论文（1267 字）mock 演示模式约 10 秒出完整报告，四团得分与 Python 版逐字段一致（金标等价）。

### 5.2 边界样例（压线字数 + 埋设作假）

```bat
set "YANZHENG_API_KEY=sk-..."
node packages\cli\bin\yanzheng.mjs testdata\fake_thesis.txt --out 边界报告.html --concurrency 3
```
实测（DeepSeek 真实评卷，AGH 与 CLI 双路径）：10082 字（压 10000 门槛线）通过门检；埋设的 4 处真值作假全部检出——数据矛盾（96.8% vs 89.3%）、消融数据不一致、捏造引用、方法-结果矛盾；总仲裁以证据链裁定一票否决（CLI 59.7/58.2/43.8 分、AGH 45.2 分，多次独立运行结论一致）。AGH 路径产物：`docs/fake_thesis_agh_real.html`。

### 5.3 失败样例（门检打回路径）

```bat
node packages\cli\bin\yanzheng.mjs 过短论文.txt --out 失败报告.html
```
实测：50 字短文 → 门检不通过即打回（不进入评卷环节），报告仅含门检结果与原因（字数不足、疑似扫描件提示）；异常路径还包括断网时在线核查自动降级、非法 API 配置返回 400、SSRF 恶意地址拦截。
