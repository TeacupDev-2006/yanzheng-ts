# 研究方向可行性判断

> 方向：B4 科研 Agent 与 Harness 工程（主赛道 B 数字计算与科研智能体）
> 项目：研证——多 Agent 互盲评卷的毕业论文质量审查系统（TypeScript 原生于 AGH 底座）
> 性质：工程可行性论证，全部论据来自本项目已完成的实测数据（2026-10）

---

## 一、待验证的核心命题

**把高考阅卷的"多评 + 仲裁 + 否决"制度工程化为多 Agent 系统，能否在分钟级、低成本下产出比单模型打分更可信、可回放的论文评审结论？**

该命题拆为三个可分别验证的子命题：

1. **机制可行性**：互盲多评能否抑制单模型的随机漂移，分差仲裁能否被确定性触发；
2. **成本可行性**：万字论文全流程（13 员 + 两级仲裁）的时延与 token 成本是否可接受；
3. **价值可行性**：系统是否具备单模型不具备的作假检出能力（而非仅"打分"）。

## 二、分维判断

### 2.1 技术可行性：高（已实测闭环）

| 论据 | 实测数据 |
|---|---|
| 端到端真实评卷 | DeepSeek 评卷档 13 次调用 + 仲裁档 3 次（分差复核×2 + 否决复核×1），全程 **141.6s / 57,932 tokens** |
| 作假检出（关键证据） | 对一篇**人为注入两处矛盾**的测试论文（摘要 95.2% vs 实验 89.3%、可疑引用），真实 LLM 评卷团检出 5 处数据不一致 + 1 处方法矛盾，总仲裁依据证据链裁定**一票否决**——这正是单模型直接打分不具备的机制性产出 |
| 确定性核心可复现 | 门检（字数/查重/必备章节）与原 Python 实现做**逐字段金标等价测试**，查重率浮点逐位一致；95 项自动化测试全绿 |
| 多 Agent 编排 | 13 员限并发并行（Promise.all 池），团内分差 >15% 确定性触发 pro 档复核，仲裁全程写 ArbitrationLog 可回放 |
| Harness 接入 | 插件通过 AGH 官方校验器全链验证（清单解析/工具注册/checkToolDef/schema 正反例/真实执行），4 工具语义声明完备（只读/审批/重放） |

**判断**：三个子命题中，机制与价值可行性已有正向实测证据；技术路线无未验证的关键假设。

### 2.2 工程可行性：高

- 单一 Node 运行时（≥24.10），pnpm monorepo 四包结构（core/cli/web/agh-plugin），构建 8/8；
- 零部署报告：单文件 HTML（内联 CSS/JS + Canvas 雷达图），离线可看、可直接分发；
- 三形态同引擎（CLI / Web / AGH 插件），配置一次生效，CI 友好（`pnpm -r test` 一键回归）；
- 评卷委员会可配置（9 家国内厂商预设 + 自定义编制），赛事切换模型零代码改动。

### 2.3 成本与数据可行性：中高（有实测锚点，规模外推有限制）

- **成本锚点**：1267 字测试论文 57,932 tokens；线性外推 1 万字论文约 **14 万 tokens / 2~4 分钟**。按国产评卷档单价估算，单篇全流程成本在**元级**——相对人工送审的人力周期（通常按周计），压缩比是数量级的；
- **限制**：外推假设 token 随篇幅近线性，超长论文（图表密集、PDF 抽取噪声）可能偏离；已留缓解手段（正文 60k 字符截断、skill 结果 3.5k 截断、按需降低编制规模）；
- **数据限制（诚实声明）**：作假检出证据来自注入式构造样本（fraud_variants + 金标），尚未在真实论文语料上做大规模盲测——这是方向内下一步最值得投入的验证工作。

### 2.4 合规可行性：中高

- 模型全部可切国产厂商（DeepSeek/Kimi/Qwen/GLM/豆包/文心/混元/星火/MiniMax 预设），第三方模型名称/版本/环节/调用方式在报告 usage_summary 中如实留痕，满足申报要求；
- 以 AGH 为运行底座，工具注册、权限审批（thesis_review 需人工批准）、执行记录导出（`agnes export` 产出 JSONL/HTML）均有官方机制支撑；
- 出站请求全部经 SSRF 守卫（仅 http/https 公网），key 存储本地不入库。

## 三、主要风险与缓解

| 风险 | 等级 | 缓解（已内置） |
|---|---|---|
| LLM 评分随机性/漂移 | 中 | 互盲多评稀释个体偏差；分差>15% 确定性触发复核；置信度<0.6 标红建议人工复核；消融开关（单员/无仲裁）支持对照实验量化收益 |
| 评卷员幻觉扣分 | 中 | skill 证据注入（查重/引用/数据一致性为确定性程序）；"skill 标注 abstain 必须回避"写入评卷 prompt；无证据不打分 |
| 超长论文 token 成本 | 低 | 分块查重、上下文截断、编制规模可调、演示模式零成本联调 |
| AGH Windows 原生构建门槛 | 低 | 阻塞点已定位（daemon 文件锁需 MSVC 编译模块），解锁路径明确（BuildTools + headers 已备）；零编译备选路线为 WSL/Linux |
| 厂商 API 演进（参数不兼容） | 低 | thinkingStyle 按厂商适配；预设目录/端点拉取/手输三通道；本地 OpenAI 兼容服务可兜底 |
| 评卷结论被误用为"最终裁决" | 中 | 报告明示"确定性近似检查 + 建议人工复核"边界；否决需证据链完整且经总仲裁复核，非单点判定 |

## 四、局限与边界（不回避）

1. 检出证据目前基于注入式样本，真实分布上的精确率/召回率待量化（评测脚本与 fraud_variants 真值已备，可扩展）；
2. 查重依赖用户自备语料，无公开源全文检索（已留 OpenAlex/Crossref 引用层核验作为部分补偿）；
3. n-gram 查重对深度改写/翻译型抄袭不敏感（嵌入混合相似度接口已预留，未默认启用）；
4. 学科适应性未验证：量规 persona 以工科/计算机论文为蓝本，人文社科需调编制（配置器已支持，无需改码）。

## 五、结论

**方向可行，且已越过"概念验证"阶段进入"证据积累"阶段。** 机制可行性有金标级工程证据，价值可行性（作假检出 + 一票否决）有注入样本上的真实检出记录，成本有实测锚点；主要未完成项是真实语料上的检出率量化与 AGH daemon 端到端执行记录的最终闭环，二者均有明确路径、无技术未知数。按当前节奏，在赛程内完成"AGH ≥3 连续步骤 + 执行记录提交"的合规闭环，风险可控。
