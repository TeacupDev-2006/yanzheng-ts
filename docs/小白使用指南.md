# 小白使用指南 —— 一步一步教你用「研证」

> 本文假设你从没接触过这个项目，也不懂编程术语。每条命令都会解释"它是什么、为什么要敲它"。

## 一、这个项目是干什么的？（一句话版）

**研证 = 一支 AI 评卷老师团队。**

你把一篇本科毕业论文交给它，它会像高考阅卷一样工作：

```
第 1 步：门卫检查（门检）——字数够不够 1 万？查重率低不低（<10%）？
         摘要/绪论/结论/参考文献这些必备章节全不全？不合格直接打回，不进入评卷。
第 2 步：13 位 AI 老师分 4 个组（内容 40 分 / 结构 30 分 / 语言 15 分 / 规范 15 分）
         同时独立打分，互相看不到对方的分数（就像高考双评）。
第 3 步：组内意见不合（分差超过 15%）→ 组长（更强的 AI 模型）复核。
第 4 步：总仲裁汇总总分；发现"疑似造假"（编造参考文献、前后数据矛盾等）
         且证据确凿 → 一票否决。
第 5 步：生成一张网页版"成绩单"：总分、雷达图、每条扣分点、修改优先级路线图。
```

## 二、三种使用方式（按难度排序）

| 方式 | 适合谁 | 一句话 |
|---|---|---|
| ① 网页版 | 所有人（推荐） | 点开网页上传论文，像投稿一样 |
| ② 命令行版 | 想批量/自动化的人 | 敲一条命令，输出报告文件 |
| ③ AGH 插件版 | 参赛/进阶用户 | 把评卷工具装进 AI 助手底座 |

## 三、准备工作（只需做一次）

### 1. 安装 Node.js（运行环境）

Node.js 就像"播放器"——这个项目是"视频文件"，没有播放器打不开。

- 打开 https://nodejs.org 下载并安装（本项目要求 **24.10 或更高版本**）
- 验证：打开命令行（Win+R 输入 `cmd` 回车），敲 `node -v`，显示 `v24.x.x` 即可

### 2. 安装 pnpm（依赖管理器）

项目用到很多别人写好的工具包，pnpm 负责帮你自动下载、摆放整齐。

```bat
npm install -g pnpm
```

- `npm` 是装 Node.js 时自带的；这条命令的意思是"用 npm 全局安装 pnpm"
- 验证：`pnpm -v`

### 3. 拿到项目代码

```bat
git clone https://github.com/TeacupDev-2006/yanzheng-ts.git
cd yanzheng-ts
```

- `git clone` = 把 GitHub 上的代码完整下载到当前文件夹
- 没装 git 的话，也可以在 GitHub 页面点绿色按钮 `Code → Download ZIP` 解压

### 4. API Key（可选！）

API Key 是 AI 厂商发给你的"通行证字符串"（形如 `sk-xxxx`），凭它调用大模型，**按用量收费**。

- **没有 Key 也能玩**：项目自带「演示模式」——AI 的回答由内置的假数据代替，不花钱、
  几秒出结果，适合先看看整个流程长什么样
- 想要真实评卷：去 DeepSeek 开放平台（platform.deepseek.com）注册充值，创建一个 key
- 也可以选其他厂商：OpenAI / Claude / Gemini / Kimi / 通义 Qwen / 智谱 GLM / Grok / MiniMax 等，
  网页版里都有预设

## 四、安装项目依赖（第一次用才需要）

在项目文件夹里依次敲：

```bat
pnpm install
```
> 把项目需要的所有第三方工具包下载到本地（相当于"装机"）。只在第一次或依赖变化后需要跑。

```bat
pnpm -r build
```
> 把人写的 TypeScript 源码编译成电脑直接执行的 JS。`-r` 表示"递归地"编译全部 4 个子包
> （core 引擎 / cli 命令行 / web 网页 / agh-plugin 插件）。

```bat
pnpm -r test
```
> 跑 95 项自检测试，确认代码在你电脑上工作正常。全绿 = 万事俱备。

## 五、方式一：网页版（推荐）

```bat
pnpm web
```

- 这条命令**启动网页服务**。敲完之后终端会"停在那里不动"——这是正常的，服务正在运行
- 浏览器打开 **http://127.0.0.1:8600**（127.0.0.1 = 你自己的电脑，8600 = 门牌号）
- **想停服务**：回到那个终端，按 `Ctrl + C`

### 页面怎么填

1. **评卷委员会配置 → 审稿人（AI）预设**：下拉选一家厂商（如 DeepSeek），
   端点和推荐型号会自动填好，你只需要粘贴自己的 API Key
   - Key 留空 = 演示模式（页面顶部会显示"演示模式"徽标）
2. **评审团编制**：默认 4 团 13 员，不懂就别动；想加团/加人/改评卷员的"视角说明"都可以
3. **上传论文**：支持 .pdf / .txt / .md，最大 20MB
4. **门检最低字数**：毕业论文填 10000（默认）；只是想试试就填小一点，比如 200
5. 点 **「送申评卷」**，等待：
   - 演示模式：几秒
   - 真实模式：约 2~4 分钟（13 位老师并行打分 + 两级仲裁），页面会显示"评卷中·请候"

### 报告怎么读

- **总分 + 等级**（优秀/良好/中等/及格/不及格）+ 右侧的「通过 / 未过 / 否决」印章
- **四团雷达图**：哪个维度薄弱一眼看出
- **修改优先级路线图**：先改什么、后改什么，按严重度排好
- **作假审查专区**：有证据的疑点列表（引用查无此文、数据前后矛盾等）
- 点开每位评卷员的折叠条：他的分数、扣分点、置信度（低于 0.6 会标红"建议人工复核"）
- 页脚：真实模式会显示耗时和 token 用量（≈花了多少钱）

## 六、方式二：命令行版

先设置 API Key（**CMD** 里用 `set`；留空则自动进演示模式）：

```bat
set YANZHENG_API_KEY=sk-你的key
```

然后一条命令评卷：

```bat
node packages\cli\bin\yanzheng.mjs 论文.txt --corpus 语料目录 --out 评卷报告.html --ppt 评卷报告.pptx
```

逐个解释：

| 部分 | 含义 |
|---|---|
| `node packages\cli\bin\yanzheng.mjs` | 用 Node 运行项目的命令行入口程序 |
| `论文.txt` | 要评的论文（.pdf/.txt/.md，换成你的真实路径） |
| `--corpus 语料目录` | 查重语料库：把怀疑被抄袭的原文（txt/md/pdf）放进一个文件夹，填文件夹路径。不给就不查重（该评卷员会"回避"该项评分） |
| `--out 评卷报告.html` | 报告输出到哪（单文件网页，双击就能看） |
| `--ppt 评卷报告.pptx` | 可选：同时导出一份 PPT 汇报版 |
| `--online` | 可选：联网核查引用真伪（Crossref）与检索相关文献（OpenAlex） |
| `--min-words 10000` | 可选：门检字数门槛 |

只想快速看效果：

```bat
pnpm demo
```
> 一键演示：自带一篇假论文和假语料，3 秒生成 `demo_评卷报告.html`，还会演示"一票否决"通路。

## 七、方式三：AGH 插件（进阶）

AGH（Agnes Harness）是本次大赛指定的"AI 助手运行底座"。本项目提供了一个插件，把
4 件评卷工具（门检 / 章节切分 / 查重取证 / 全流程评卷）注册进 AGH，让 AI 助手在对话中
自主调用它们完成"门检→取证→评卷"的完整工作流。安装与闭环验证步骤见
[操作手册](操作手册.md) 第 4 节。

## 八、常见问题

- **一定要 API Key 吗？** 不。没 Key 就是演示模式，走完全一样的流程，只是 AI 回答是假数据。
- **演示和真实差在哪？** 真实模式才会真的"读"你的论文内容来打分；演示模式的分数是固定的。
- **报告显示"打回"？** 门检没过（字数不足 / 查重超标 / 缺必备章节），按报告里的清单改论文后再投。
- **查重是怎么算的？** 论文切成 400 字的块，逐块和语料比对相似度，取最高值；低于 10% 才放行。
- **费用多少？** 报告页脚有 token 统计。经验值：1 万字论文真实评卷 ≈ 14 万 tokens ≈ 2~4 分钟。
- **8600 端口被占用？** 换端口：CMD 里 `set PORT=8700` 再 `pnpm web`。
- **命令敲完没反应 / 报"不是内部或外部命令"？** 多半是抄了文档里的注释行（`#` 开头）——
  CMD 不认识 `#`，只敲命令本身。
