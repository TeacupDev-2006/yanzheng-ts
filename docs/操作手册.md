## 2. CLI 形态

```bash
# 构建 bin（已构建可跳过）
pnpm --filter @yanzheng/cli build

# 演示（mock，秒级）
pnpm demo   # 产出 demo_评卷报告.html

# 真实评卷
node packages/cli/bin/yanzheng.mjs 论文.pdf \
  --corpus 语料目录 --online \
  --api-key sk-xxx \
  --out 评卷报告.html --ppt 评卷报告.pptx \
  --min-words 10000
```

- `--corpus`：自备查重语料目录（.txt/.md/.pdf 递归）
- `--online`：Crossref 引用验真 + OpenAlex 文献检索（离线自动降级并在证据中注明）
- 门检不过（字数/查重/必备章节）直接打回，报告只含打回清单

## 3. Web 形态

```bat
pnpm web
```

默认 8600 端口，浏览器打开 http://127.0.0.1:8600（投稿页 → 送审评卷 → 直接返回 HTML 报告）。
端点：`GET /`（投稿页 + 评卷委员会配置器）、`POST /review`（multipart：file/min_words/online/rubric_json/llm_key/llm_base_url/model_judge/model_arbiter）、`GET /health`。

### 配置器用法

- **自选 AI（12 家预设）**：DeepSeek / OpenAI / Anthropic(Claude) / Google Gemini / Kimi(月之暗面) / Qwen(阿里云百炼) / GLM(智谱) / xAI(Grok) / MiniMax / OpenRouter(聚合) / Agnes 赛事端点 / 自定义 OpenAI 兼容端点。选预设自动填官方兼容端点与推荐型号；各家 API key 自备，key 留空时为演示模式（确定性 mock）。端点仅允许 http/https（本地服务如 `http://127.0.0.1:11434/v1` 可用）。
- **具体模型选择**：两个模型档输入框均带下拉建议——各厂商预设内置常用型号目录（评卷档=快/便宜，仲裁档=旗舰/思考，如 `deepseek-flash`/`gpt-5-mini`/`claude-haiku-4-5`/`gemini-2.5-flash`/`kimi-k2-turbo-preview`/`qwen-flash`/`glm-4.5-flash`/`grok-4-fast` 等）；目录可能滞后于官方上新，可点「从端点拉取模型列表」取回真实型号——**拉取仅支持公网端点（SSRF 守卫）**，OpenRouter 聚合数百个型号；本地/内网推理服务可作评卷端点但拉取不可用，型号直接手输。
- **思考开关自动适配**：DeepSeek V4 的 `thinking` 私有参数仅对 DeepSeek/Agnes/自定义预设随请求发送；OpenAI/Anthropic/Gemini/Kimi/Qwen/GLM/xAI/MiniMax/OpenRouter 预设自动不携带（第三方端点对未知参数报 400），由引擎 `thinkingStyle` 选项控制，CLI/SDK 亦可显式指定。
- **评审团编制**：「＋添加评审团」加整团（可设团名与团满分）；团内「＋添加评卷员」加员，每员可改名称、评卷视角（persona）、勾选技能、选模型档。「删除本团/删除」随时收缩编制，「恢复默认编制」回到标准 4 团 13 员。
- **缩放规则**：及格线 = 编制总分 × 60%；优秀/良好/中等/及格分档按编制总分等比缩放（如总分 110 时优秀线为 99）。
- 编制以 JSON（`rubric_json`）随表单提交，服务端经 `normalizePanels` 校验（至少 1 团、每团至少 1 员、满分正数、id 去重、未知技能过滤）。

真实评卷模式（先设 key 再启动）：

```bat
set DEEPSEEK_API_KEY=sk-你的key
pnpm web
```

PowerShell 用 `$env:DEEPSEEK_API_KEY="sk-你的key"`；Git Bash 用 `DEEPSEEK_API_KEY=sk-你的key pnpm web`。
无 key 时自动进入演示模式（确定性 mock，页面有徽标标注）。

## 4. AGH 插件形态

插件包发布布局（`packages/agh-plugin/`）：`package.json`（agnes.plugins 清单）+ `dist/index.js`（自包含）+ `skill/thesis-review/SKILL.md`。

### 4.1 机制级校验（无需 daemon，Windows 可跑）

```bash
cd /d/ZCode/agnes-harness
node_modules/.bin/tsx "<本仓库>/scripts/agh-manifest-verify.mts"
```

用 AGH 官方解析器/校验器验证：清单声明、工具注册、checkToolDef、schema 正反例、4 工具真实执行。

### 4.2 真实 daemon 闭环（≥3 连续步骤 + 执行记录导出）

```bash
node "<本仓库>/scripts/agh-e2e.mjs"
```

脚本自动完成：隔离 AGH_HOME（D:/ZCode/agh-home）→ SDK 直连 daemon →
inspect/install/trust/enable 插件 → 回环 provider 夹具（AGH 官方验收机制，无真实模型账号）→
会话内连续执行 `thesis_gate → thesis_sections → thesis_review`（含审批流）→
`agnes export` 导出 `docs/AGH执行记录.jsonl/.html`。

前置：AGH CLI 本地分发已构建（见下节）。

### 4.3 AGH 本地构建（Windows 一次性准备）

Windows 下 daemon 需要 `@agnes/system-node` 原生模块（私有 DACL 文件锁，无 JS 回退）：

```powershell
# 1) VS C++ Build Tools（管理员，约 2-4 GB）
winget install --id Microsoft.VisualStudio.2022.BuildTools --override `
  '--quiet --wait --norestart --add Microsoft.VisualStudio.Component.VC.Tools.x86.x64 --add Microsoft.VisualStudio.Component.Windows11SDK.26100' `
  --accept-source-agreements --accept-package-agreements

# 2) Node headers + node.lib（本仓库已备好：D:/ZCode/node-headers/24.21.0，
#    或用官方脚本 .github/scripts/prepare-windows-native.ps1 重新下载）
$env:AGNES_NODE_HEADERS = 'D:/ZCode/node-headers/24.21.0'

# 3) 构建（在 D:/ZCode/agnes-harness）
pnpm --filter @agnes/system-node build:native   # 产出 packages/system-node/dist/native/agnes-system.node
pnpm --filter @agnes/cli build:local            # 产出 packages/cli/dist/local/agnes.mjs
```

### 4.4 手动操作插件（等价 CLI 流程）

```bash
cd /d/ZCode/agnes-harness
export AGH_HOME="D:/ZCode/agh-home" AGNES_PROFILE=local-dev
AGH=packages/cli/dist/local/agnes.mjs
node $AGH package inspect file:/d/ZCode/agh-plugins/yanzheng-thesis-review   # TTY 下 y 确认 install
node $AGH package trust @yanzheng/agh-plugin <integrity> <capabilityHash>
node $AGH package enable @yanzheng/agh-plugin
node $AGH package status    # 期望 actual=running trusted=true
```

## 5. 模型与赛事合规

- 模型名：评卷 `deepseek-flash`（非思考）/ 仲裁 `deepseek-v4-pro`（思考）；旧名 deepseek-chat/reasoner 已废弃
- 切 Agnes 赛事模型：设 `YANZHENG_LLM_BASE_URL` + `YANZHENG_MODEL_JUDGE/ARBITER` + `YANZHENG_API_KEY`，零代码改动
- 报告尾注与 usage_summary 记录各模型 token 用量与耗时（真实评卷 1 万字论文约 14 万 tokens / 2-4 分钟）
- 出站请求（Crossref/OpenAlex）全部经 SSRF 守卫（仅 http/https 公网地址，解析地址逐一校验）
