# 网页端 AI 评审提示词（用于与研证系统对比）

> 用途：在 DeepSeek / ChatGPT / Kimi 等大模型聊天网页中，直接粘贴以下提示词 + 论文文本，
> 得到"裸 LLM 评审"的结果，与研证系统的输出做对比。
> 设计原则：给裸 LLM **最好的条件**（详细的评审判词、明确的输出格式）——对比才有说服力。

## 使用方法

1. 打开任意大模型聊天网页（DeepSeek 官网 / ChatGPT / Kimi 均可）
2. 复制下面的提示词，紧接着粘贴论文全文（或先发提示词、再发论文，分两条消息）
3. 等待输出，保存这次对话（对比镜头素材）
4. 再用研证评卷同一篇论文，两边并排对比

---

## 提示词 A · 简单版（普通用户的直觉做法）

```text
请评审这篇本科毕业论文，指出优点和不足，并给出总体评价。

论文如下：
【在此粘贴论文全文】
```

> 预期表现：会得到一段泛泛的点评（有优点有不足），但**没有分数体系、没有逐条定位、
> 每次刷新结果都不同、无法验证它是否真的读过论文**——这正是对比的起点。

---

## 提示词 B · 详细版（模拟研证的评审框架，给裸 LLM 最好的条件）

```text
你是一名严格的高校毕业论文评审专家。请对下面这篇本科毕业论文进行全面的 Qualität 评审，严格按照以下要求输出：

【评审框架】
从四个维度分别独立评分（满分 100 分，权重如下）：
1. 内容审题（40 分）：选题意义、问题定义、研究目标、创新性、论证充实度
2. 结构逻辑（30 分）：章节架构完整性、论证链条连贯性、方法与技术路线合理性
3. 语言表达（15 分）：术语准确性、表达流畅度、学术文风一致性
4. 规范核查（15 分）：引用著录格式、图表编号、目录完整性、格式规范

【输出要求】
1. 每个维度给出 0 到满分之间的分数（保留一位小数），并合成总分
2. 每个维度至少列出 2 条具体扣分点，每条扣分点必须包含：
   - 定位（精确到章节/段落）
   - 问题描述
   - 可执行的修改建议
   - 扣分值
3. 单独一节"学术诚信审查"：逐条检查参考文献列表是否存在可疑条目（编造的期刊/卷期、
   作者与标题不匹配），检查正文中同一指标的数据表述是否前后一致，发现可疑之处必须
   给出具体定位与理由，并说明该疑点是否达到"一票否决"的严重程度
4. 给出总体结论：通过 / 不通过，以及一份按优先级排序的修改路线图

【约束】
- 只依据论文文本本身评审，不得臆造论文中不存在的内容
- 对每个判断注明依据（引用原文片段）
- 严格按上述结构输出，不要遗漏任何一节

论文如下：
【在此粘贴论文全文】
```

> 预期表现：这是裸 LLM 能做到的**上限**——结构化的四维评分、扣分点定位、诚信审查。
> 录制对比时用这个版本，评委才能看到"我们已经给了它最详细的指导"。

## 提示词 C · 数据矛盾专项（配合造假论文演示）

针对 `testdata\fake_thesis.txt`（内含 4 处注入作假，真值见 `fake_thesis_truth.json`）：

```text
你是一名学术诚信审查专家。请仔细阅读下面的论文全文，逐节排查以下类型的学术不端：
1. 数据不一致：同一指标（如准确率、时延、样本量）在不同章节的数值是否矛盾
2. 消融实验矛盾：消融实验的设置与结果数字是否自洽、各模块贡献之和是否与总数一致
3. 捏造引用：参考文献列表中是否存在可疑条目（期刊卷期不合理、查无此文）
4. 方法与结果矛盾：方法章节声称的技术路线与实验章节的实际内容是否一致

对每一处发现，给出：章节定位、原文数据、矛盾说明、严重程度（严重/较重/轻微）。
最后给出结论：该论文是否存在足以否决的学术不端。

论文全文如下：
【在此粘贴论文全文】
```

## 对比论证要点（录制旁白可直接引用）

| 维度 | 裸 LLM（提示词 B） | 研证系统 |
|---|---|---|
| 评分稳定性 | 同一论文多次提问，分数波动 | 13 员互盲 + 仲裁，分数可复现（消融开关支持对照） |
| 查重 | 无法执行——只能"声称"检查 | 分块 n-gram + 词袋混合真实计算，量化重复率 |
| 引用验真 | 只能凭参数知识猜测 | 逐条调用 Crossref 真实验证，无命中即标记 |
| 撤稿核验 | 无此能力 | 对接 Retraction Watch 撤稿索引自动标记 |
| 数据矛盾检出 | 靠通读运气（长文易漏） | data_consistency skill 确定性抽取比对 |
| 作假否决 | 无机制 | 证据链复核 → 一票否决 |
| 过程留痕 | 关网页即消失 | AGH 执行记录 84 行工具调用事件可人工核查 |
| 审批与安全 | 无 | 写文件/调模型前弹权限审批 |

**录制话术（对比一结尾）**：
"我们给它的提示词已经足够详细，它的表现也确实不错——结构化、有扣分点、甚至发现了部分矛盾。
但请注意三个它**做不到**的事情：它说查重了，可它根本没有数据库可查；
它说验证了引用，可它连一篇真文献都没检索过；它给了分数，可你关掉网页就再也无从复盘。
而研证把这三件事全部变成了**可执行的程序与可核查的记录**。"

## 一个重要的诚实声明（答辩被追问时用）

裸 LLM 对比实验的公平性说明：提示词 B 已经把研证的评审框架尽可能完整地注入给裸 LLM，
因此该对比展示的是"**多评仲裁制度 + 确定性证据工具 + 执行留痕底座**"带来的增量，
而非模型能力的差距。若评委追问"为什么不用更好的模型"——研证支持任意模型接入
（9 家国内厂商预设 + 自定义端点），框架与模型解耦，换成任何旗舰模型结论的机制部分不变。
